# 双视角识别与抓取接口

## 当前范围

两相机固定、物块静止、平底托盘上的直立规则实体。颜色与几何类别独立：颜色是 HSV 粗分类（12 个色相加黑/白/灰），不是物块类型的输入。颜色名和阈值仍需当前光照的实物色卡验证。

类别契约：cube、cuboid、cone、cylinder、ball、regular_tetrahedron、triangular_pyramid、square_pyramid、pentagonal_pyramid、hexagonal_pyramid、triangular_prism、pentagonal_prism、hexagonal_prism。正四面体是三棱锥的特殊几何情形；仅凭类别名称不同不代表存在可观测差异。侧倒、叠放和严重遮挡不属于当前模型的已验证能力。

## 坐标约定

- 单位全部为 mm；托盘 x/y 沿标定 JSON 定义，原点在平底左上角。
- 接口高度正方向始终为离开托盘平面；这与原始 PnP 托盘系 z 的符号可能不同。
- `T_robot_from_tray_mm` 是原始 PnP 托盘坐标到机器人基座的刚体 4x4 变换，平移单位 mm。只有投影/变换边界应用 `raw_z = up_sign * height`。
- `descend_z_mm` 表示托盘平面上方的目标夹持中心高度，不是相对当前位置下降的距离，也不是机器人 TCP 的绝对 z。
- `approach_z_mm` 表示托盘上方预抓取高度；默认是整盘已观测物体最高点加 20mm，是可调候选参数。场景有未确定三维几何的障碍物时，所有自动抓取候选暂停。
- 抓取中心默认按总高度的 0.5 比例选择；它不是物体质心模型。球、锥和棱锥的夹持接触形状需要实物确认。
- `yaw_deg` 是手指长轴在托盘 xy 平面的方向，夹爪闭合轴是 yaw+90°。圆形对称物体 yaw 可为空；控制侧应选经可达性/碰撞校验的方向。
- 坐标变换结果不是 TCP 目标；工具长度、夹持中心到 TCP 的偏置、夹爪姿态、IK 和碰撞校验必须在机器人集成层完成。

## 三维模型拟合

`scripts/two_view_model_fit.py` 使用 OpenCV 标定投影和 SciPy 有界最小二乘，同时解释俯视与侧视的完整轮廓。残差是两视图双向边界点到线段的距离，不把地面单应或侧视投影占用比例当作真实截面。球体使用每台相机对应的透视切圆；棱柱/棱锥用真实三维顶点与棱边投影。

模型拟合同时恢复中心 x/y、尺寸、高度和朝向；按绝对残差、最差边界误差、最优/次优模型差距、托盘范围和高度上限判断接受。cube 从三维长方体近等尺寸派生；regular_tetrahedron 从正三角底面与相应三维高度比例派生。模型假设为直立、完整可见凸实体；拒判不是实现失败，而是输出契约的一部分。

这是带实时入口的混合版本：`scripts/two_view_live.py` 负责采集与显示，拟合仍按实例搜索多个模型和 yaw 初值。稳定场景会复用上一轮各族初值（仍然比较全部模型，每 10 次或场景明显变化恢复完整搜索），单块约 0.6~1.3 秒；多块整场景仍要 9~28 秒，超过 8 秒结果有效期就会显示过期。旧轮廓查表只保留为诊断回退，回退结果不进入有效抓取坐标。

识别工作区由 `scripts/vision_workspace.py` 决定：优先用 `tray.outer_corners_px`（人工在画面上点的四点）按原样使用，没有时退回黑点四点 `tray.corners_px`；`slope_width_mm` 不再参与内缩——它是四点之外的距离，重复扣减会把贴边物块裁成长条。迁移与重建步骤见 [迁移到新电脑.md](迁移到新电脑.md)。

## 只读离线回放

使用当前朝向采集的两路图像与相同相机参数的空托盘参照图。离线输入是掩膜时，不需要参照图；非零值表示物块。

```powershell
Set-Location D:\code\src\sight
$env:PYTHONPATH = 'D:\code\src\sight\.venv\Lib\site-packages'
$py = 'C:\Users\123\AppData\Local\Programs\Python\Python313\python.exe'
& $py scripts\two_view_shape.py --input-masks `
  --offline-vertical PATH_TO_VERTICAL_MASK.png `
  --offline-side PATH_TO_SIDE_MASK.png `
  --calibration 配置\calibration_stereo.json `
  --output-json captures\offline_result.json
```

原始彩色图去掉 `--input-masks`，用 `--ref-dir` 指定含 `ref_vertical.jpg`、`ref_side_a.jpg` 的目录。离线分支不创建相机句柄或 GUI。`--min-area` 默认 2500px，小尺寸合成图可显式减小。

## 工具/机械臂配置

实际数字应来自测量，不要把示例单位矩阵写入生产标定。标定 JSON 可新增 `robot` 对象：

- `robot.T_robot_from_tray_mm`: 有限、旋转正交且 det=+1 的 4x4 刚体矩阵。
- `robot.gripper.opening_range_mm`: [最小可闭合宽度, 最大张开宽度]。
- `robot.gripper.clearance_mm`: 单侧预张开余量，非负。
- `robot.gripper.approach_clearance_mm`: 物体顶上方预抓取余量，非负。

夹爪开口也可用 `--gripper-min-opening-mm` 与 `--gripper-max-opening-mm` 同时提供。代码分别检查接触宽度是否能闭合、预张开宽度是否超行程。净空是物体包络之间/与平底边缘之间的几何距离，不替代完整手指和机械臂的扫掠体碰撞检查。

## 抓取排序优先级

先筛掉三维拟合未通过、关联不确定、净空不足、夹爪无法闭合/张开等候选；合格候选按以下顺序逐级比较：识别质量评分更高 → 最优与次优类别的拟合差距更大 → 模型拟合误差更小 → 净空更大。净空不再通过加权总分抵消识别不确定性；目标是优先抓类型最清楚、几何最可靠且夹爪条件满足的物块。评分是模型质量指标，不是实测抓取成功概率。

## 输出与状态

输出 JSON 包含 object_id、class、appearance、geometry_valid、position_mm、dimensions_mm、grasp_target、clearance_mm、rank、pick_candidate、robot_target_xyz_mm、robot_target_ready、robot_command_ready、rejection_reasons 和 evidence。

- 有效几何才进入 position_mm / dimensions_mm / grasp_target；未校正估计放入 unverified_estimates，主目标字段为 null。
- shape_hypothesis 是诊断假设，不代表分类已接受；confidence_score 是质量评分而非校准概率。
- pick_candidate 表示感知几何与配置检查通过，仍需要工具/TCP、运动规划和实物确认。
- 无相机阶段 robot_target_ready 与 robot_command_ready 保持 false；代码不发送动作。
- 不确定关联、共享侧视连通域、拟合不合格、夹爪限制、缺标定等写入 rejection_reasons。
- object_id 只在当前帧内有效，尚非跨帧跟踪 ID；两路 USB 顺序读取尚不等价于曝光同步。

## 验收清单

离线：两视图由真实三维模型分别投影；验证 x/y/尺寸/高度、形状混淆拒判、NaN/缩放变换拒绝、Z 正负转换、夹爪闭合与预张开、颜色跨 hue=0 边界、无相机 CLI 和严格 JSON。

待实测：当前朝向各类别与 >10 种颜色；白块/反光/阴影/曝光漂移；粘连和遮挡；标定与托盘位置变化；双路时间偏差；位置 P95≤2mm、高度 P95≤3mm；TCP 偏置与工具 yaw 定义；夹爪行程/力控；IK、运动极限、轨迹扫掠碰撞；至少 100 次低速独立抓取验证。

只有完成上述集成与实物验证，才能对完整机器人抓取作验收结论。合成测试证明软件逻辑与理想模型，不证明真实相机下的总体准确率或抓取成功率。
