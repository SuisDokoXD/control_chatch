# 迁移到另一台电脑（Windows）

目标：在新机器上复现当前双相机 OpenCV 识别，并知道哪些东西必须重做、哪些能直接复用。
本文只覆盖“让程序在新机器跑起来并给出可信结果”，不涉及机械臂执行。

## 0. 先看清：什么进了仓库，什么没有

进仓库（clone 就有）：

- `程序/`、`scripts/`、`tests/`
- `配置/camera_roles.json`、`配置/camera_settings.json`、`配置/calibration_stereo.json`、`配置/objects.json`、`配置/扩展/`
- `文档/`、`README.md`、`requirements.txt`、启动脚本

不进仓库（本机生成或体积大，新机器必须重建）：

| 内容 | 位置 | 原因 |
| --- | --- | --- |
| 虚拟环境 | `.venv/` | 本机路径/二进制，必须新建 |
| 空盘参照帧 | `captures/calibration/ref_*.jpg`、`ref_static_vertical.png` | 曝光和光照绑定当次采集，必须重采 |
| 采集与调优证据 | `captures/`、`reports/` | 体积大，属调试产物 |
| 数据集 | `dataset/`、`dataset_backup_*/` | 体积大 |
| 模型/图纸/权重 | `model/`、`权重/`、`*.pt` | 体积大，非源码 |
| 临时文件 | `tmp/` | 可丢弃 |

**关键提醒**：`配置/calibration_stereo.json` 会跟着仓库走，但它只对“同一套相机 + 同一装配位置 + 同一分辨率”成立。整机原样搬过去可以直接用；换了相机、换了支架、换了 USB 采集卡或分辨率，就必须重新标定，否则毫米换算和高度会整体偏。

## 1. 新电脑拉代码

```powershell
git clone -b 最小运行版本 https://github.com/SuisDokoXD/control_chatch.git sight
Set-Location sight
```

仓库名是 `control_chatch`，本地目录可以叫 `sight`；代码全部用相对项目根目录的路径，不依赖目录名。

## 2. 建环境

当前验证环境：Windows + Python 3.13.7 64 位。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -c "import cv2,numpy,scipy,PIL;print(cv2.__version__,scipy.__version__,PIL.__version__)"
```

依赖：opencv-python、numpy、scipy（三维拟合）、Pillow（中文标注），ultralytics 仅老训练链路需要。

旧机器上“系统 py -3.13 + `$env:PYTHONPATH=.venv\Lib\site-packages`”是为了绕开当时摄像头打不开的问题。新机器优先直接用 `.venv\Scripts\python.exe`；只有它打不开相机时，再回退成同样写法：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) '.venv\Lib\site-packages'
py -3.13 scripts\two_view_shape.py --exposure -4
```

## 3. 确认相机编号

设备枚举顺序会随 USB 口、重启、插拔变化，换机器必然要重认。

```powershell
.\.venv\Scripts\python.exe 程序\camera_probe.py --max-index 9
# 或带窗口逐个看
.\.venv\Scripts\python.exe scripts\probe_cameras_visual.py
```

把俯视相机编号填到 `配置/camera_roles.json` 的 `vertical.index`，侧视填 `side_a.index`。
判据：俯视这一路托盘应接近正对（托盘长宽比接近真实尺寸比），侧视应明显斜视、有透视压缩。

## 4. 标定（三件事，别混）

| 步骤 | 命令 | 产出 |
| --- | --- | --- |
| 内参 + 双目外参 | `.\.venv\Scripts\python.exe scripts\calibrate_stereo.py` | `calibration_stereo.json` 的 `intrinsics` / `extrinsics` |
| 托盘平底黑点 → 毫米单应 | `.\.venv\Scripts\python.exe scripts\calibrate_tray_plane.py --width-mm 159.84 --height-mm 173.29` | `tray.size_mm`、`tray.corners_px`、`homography_*`、`px_per_mm` |
| 手动四点工作区（识别边界） | `.\.venv\Scripts\python.exe scripts\mark_tray_outer.py` | `tray.outer_corners_px`、`slope_width_mm` |

三者分工不同，不要互相替代：

- 黑点四点 = 平底平面，用来做像素↔毫米换算和托盘位姿；
- 手动四点 = 当前程序实际识别/裁剪的工作区（`scripts/vision_workspace.py` 优先用它，按 TL/TR/BR/BL 原样使用，不再做斜坡内缩）；
- 标定尺寸要填**平底实测**长宽，`159.84 × 173.29 mm` 是当前托盘的值，换托盘要改成实测值。

验收：

```powershell
.\.venv\Scripts\python.exe scripts\verify_tray_stereo.py
.\.venv\Scripts\python.exe scripts\verify_stereo_calibration.py
```

网格外框要和托盘“平底→斜坡”折线重合；不重合说明黑点认错或尺寸填错。

## 5. 重采空盘参照帧（必须）

`captures/` 不在仓库，新机器一条参照帧都没有。清空托盘（含小块、不要有手）后：

```powershell
.\.venv\Scripts\python.exe scripts\two_view_shape.py --capture-ref --exposure -4
```

自检不通过会明确拒绝写入（平底里还能看到物块）。失败就清盘重来，**不要**把有物块的画面当空盘存进去——那会让后续全部识别拿残影当背景。

曝光：当前光照实测 `-4`（过曝 < 2%）。换机器/换灯先重扫：

```powershell
.\.venv\Scripts\python.exe scripts\tune_camera_exposure.py --index 1 --index 2
```

## 6. 跑识别

实时（双相机 + 可视化窗口）：

```powershell
.\.venv\Scripts\python.exe scripts\two_view_shape.py --exposure -4 --jsonl --session-dir reports\run_new
```

- 窗口标题 `Two-view OpenCV`，`Q`/`Esc` 退出，`S` 存当前叠加图。
- `--session-dir` 会把每帧双路原图、掩膜、叠加图、`telemetry.jsonl`、`fits.jsonl` 存档，便于事后复查。
- 结果文件：`captures/preview/live_check/live_result.json`（当前目标）、`live_status.json`（时效/状态）。下游必须检查 `observation.valid_until_unix`。

离线回放（不碰相机）：

```powershell
.\.venv\Scripts\python.exe scripts\two_view_shape.py --input-masks `
  --offline-vertical PATH\vertical_mask.png --offline-side PATH\side_mask.png `
  --output-json captures\offline_result.json
```

原始彩图去掉 `--input-masks`，用 `--ref-dir` 指向含 `ref_vertical.jpg`、`ref_side_a.jpg` 的目录。

## 7. 验收

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前基线：**130 项全通过**。再跑一次实时窗口 60 秒以上，确认：两路画面正常、能出目标、`live_status.json` 状态不是一直 `expired`。

## 8. 已知问题（换机器后照旧存在，不是迁移没做好）

- **性能**：多物块时整场景拟合 9–28 秒，超过 8 秒有效期就会显示“过期”。表现是有轮廓、没类别/坐标。这是当前实现瓶颈，不是新机器配置问题。
- **正方体高度偏低**：模型拟合出约 47.5×47.0×32.1 mm（实物接近等边），长宽对、高度偏，所以标成 cuboid 且未通过接受门槛。
- **粘连与遮挡**：多块挨近时掩膜连通，触发“轮廓非凸/共享连通域”拒判。
- 纯 OpenCV 几何拟合，无训练模型；不发机械臂指令，`robot_command_ready` 保持 `false`。
